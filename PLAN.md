# PLAN — QR Menu for Cafe: шлях до продакшену

Дорожня карта рефакторингу та доведення проєкту до продакшену. Оновлюється в міру виконання.

## Рішення (зафіксовані на інтерв'ю)

| # | Питання | Рішення |
|---|---------|---------|
| 1 | Backend | **Supabase** (Postgres + Auth + Storage + RLS) |

## Поточний стан (аудит 2026-08-13)

- Next.js 16.3 App Router, React 19.2, Tailwind CSS 4, `motion`, `qrcode`; усе — клієнтські компоненти (`'use client'`). Роути: `/` (гостьове меню), `/admin` (кабінет власника + вхід), `/admin/profile` (профіль / зміна пароля) — усі статичні.
- Усі дані в Supabase (Postgres + Auth + Storage + Realtime); `localStorage` — лише мова інтерфейсу (`qr_menu_lang`). QR-коди столиків зберігаються в бакеті `qr-codes`.
- Тримовний словник `TRANSLATIONS` у `lib/store.tsx`, тримовна модель даних (`*Ua/*En/*Hu`).
- **35 тестів** (4 файли, спільний in-memory фейк Supabase у `lib/__fixtures__/`); `lint` і `next build` чисті.
- **Production live**: `https://qrmenu-omega-azure.vercel.app` (HTTP-smoke ✅; інтерактивну перевірку чекаємо від користувача).
- Дрібниці: README переписано під Supabase-архітектуру; невикористані залежності прибрано (13.08).
